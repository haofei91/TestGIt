# 应用与设备

> 本文档覆盖模块：AutoJs6（本体应用）、App（通用应用）、Device（设备）、Shell、Shizuku  
> 对应官方文档：[AutoJs6](https://docs.autojs6.com/autojs) | [App](https://docs.autojs6.com/app) | [Device](https://docs.autojs6.com/device) | [Shell](https://docs.autojs6.com/shell) | [Shizuku](https://docs.autojs6.com/shizuku)

## 概述

这五类 API 共同支撑脚本与 **AutoJs6 自身**、**其他应用**、**系统设备信息/控制**、**本地 Shell** 以及 **Shizuku（ADB 级特权）** 的交互：

| 能力域 | JS 入口 | 典型用途 |
|--------|---------|----------|
| 本体应用 | `autojs` | 版本与 Root/权限/语言/主题、重启与退出宿主等 |
| 通用应用 | `app` | 启动应用、Intent、打开文件/网页、卸载、双开相关扩展等 |
| 设备 | `device` | 屏幕尺寸、Build 信息、IMEI/AndroidId/MAC、亮度音量、唤醒振动等 |
| Shell | `shell()` / `shell` 模块 / `Shell` 类 | 同步执行命令、长会话 Shell、按键注入等 |
| Shizuku | `shizuku` | 在 Shizuku 可用时以特权执行 shell，避免依赖传统 root |

运行时通过 `ScriptRuntime.augment()` 将各 **augment 桥接类** 挂到全局；`app` 还与 `ScriptRuntime.app`（`AppUtils`）及打包信息交织。下文表格给出 **桥接注册行号** 与 **实现文件**，便于对照源码阅读。

## AutoJs6 - 本体应用

### 模块概述

`autojs` 描述 **当前 AutoJs6 宿主应用** 的版本信息、界面语言、Root 检测策略、关键特殊权限是否已授予，以及 **重启/退出** 宿主等。官方文档另包含 `themeColor`、`R` 资源代理等（见 [autojs 文档](https://docs.autojs6.com/autojs)）。

子对象 **`autojs.version`** 由 `Version.kt` 以 `augmentWithRuntime` 挂到 `autojs` 上（见 `ScriptRuntime.kt` 第 752 行），提供版本比较方法。

同一套能力也可通过 **`app.autojs`** 访问（`ScriptRuntime` 在 augment 末尾将 `augmentedAutojs` 赋给 `app.autojs`）。

### 源码定位

| 类型 | 位置 |
|------|------|
| 桥接主类 | `runtime/api/augment/autojs/Autojs.kt` — `selfAssignmentProperties` / `selfAssignmentFunctions` / `selfAssignmentGetters` |
| 版本子对象 | `runtime/api/augment/autojs/Version.kt` — `code`/`name`/`date` 与 `isEqual` 等 |
| 注册 | `runtime/ScriptRuntime.kt` 约 751–753 行：`Autojs(this).augment(...)` 与 `AutojsVersion.augmentWithRuntime(autojs, ...)` |

### 详细 API（节选与官方对齐）

以下与 [docs.autojs6.com/autojs](https://docs.autojs6.com/autojs) 一致；实现见 `Autojs.kt` 与 `org.autojs.autojs.util.RootUtils`、`IntentUtils` 等。

#### `autojs.getLanguage()` / `autojs.getLanguageTag()`

- **签名**：`getLanguage()` → `java.util.Locale`；`getLanguageTag()` → `string`  
- **说明**：语言来自应用偏好 `Language.getPrefLanguage()`。  
- **桥接**：`runtime/api/augment/autojs/Autojs.kt`（`getLanguage` / `getLanguageTag`）  
- **示例**：

```js
console.log(autojs.getLanguageTag());
i18n.setLocale(autojs.getLanguageTag());
```

#### `autojs.setRootMode(rootMode, isWriteIntoPreference?)`

- **签名**：第一参数可为 `RootMode`、`number`（如 -1/0/1）、`boolean`、`'auto'|'root'|'non-root'`；第二参数可选，是否写入偏好。  
- **返回值**：`void`  
- **桥接**：`Autojs.kt` → `RootUtils.setRootMode`  
- **示例**：

```js
autojs.setRootMode('root');
autojs.setRootMode(RootMode.FORCE_ROOT, true);
```

#### `autojs.version`（`Version.kt`）

- **属性**：`autojs.version.name` / `code` / `date` 与顶层 `versionName` 等对应。  
- **方法**：  
  - `isEqual(otherVersion)`  
  - `isHigherThan(otherVersion)`  
  - `isLowerThan(otherVersion)`  
  - `isAtLeast(otherVersion)`  
  - `isAtLeast(otherVersion, ignoreSuffix)`（第二参数为 `boolean` 时忽略后缀比较）  
- **桥接**：`runtime/api/augment/autojs/Version.kt`  
- **实现**：`io.github.g00fy2.versioncompare.Version`  
- **示例**：

```js
if (autojs.version.isAtLeast('6.2.0', true)) { /* ... */ }
```

#### `autojs.restart` / `autojs.exit`

- **签名**：`restart()`、`restart(scriptPath)`、`restart([path1, path2])`（`exit` 同构）  
- **说明**：无参时调用 `IntentUtils.App.restart/exit`；传入脚本时在重启后调度执行。  
- **桥接**：`Autojs.kt`  
- **示例**：

```js
autojs.restart('@'); // 重启后重新运行当前脚本
```

## App - 通用应用

### 模块概述

`app` 模块负责 **启动/查询应用**、构造 **Intent**、**打开 URL/文件**、**发邮件**、**发广播**、以及 **双开（dual）**、**root/shizuku** 辅助启动等。官方 [App 章节](https://docs.autojs6.com/app) 仍部分沿用 Auto.js 描述；AutoJs6 在 `App.kt` 中扩展了大量别名与行为（如 `openAppSetting` 映射到 `launchAppDetailsSettings`）。

### 源码定位

| 类型 | 位置 |

下列均给出：**JS 签名**、**参数**、**返回值**、**桥接文件**、**Android 实现要点**、**示例**。

#### `app.launch(packageName)` / `app.launchPackage` / `app.launchApp(appName)`

- **签名**：`launch(app)` / `launchPackage(packageName)` / `launchApp(appName)` → `boolean`  
- **参数**：包名、预设别名（`PresetApp`）、或应用显示名。  
- **返回值**：是否成功发起启动（内部 `PackageManager.getLaunchIntentForPackage`）。  
- **桥接**：`App.kt` → `scriptRuntime.app`（`AppUtils`）  
- **实现**：`AppUtils.launchPackage` / `launchApp`  
- **示例**：


#### `app.getPackageName(appName)` / `app.getAppName(packageName)`

- **签名**：各接受一个 `string` → `string | null`  
- **说明**：遍历已安装应用标签匹配名称；多同名时取其一。  
- **桥接**：`App.kt`  
- **实现**：`AppUtils.getPackageName` / `getAppName`  

#### `openAppSetting`（`launchAppDetailsSettings`）

- **签名**：`launchAppDetailsSettings(pkg)` 或全局别名 `openAppSetting(pkg)` 等 → `boolean`  
- **桥接**：`App.kt` 别名列表含 `openAppSetting`  
- **实现**：`AppUtils.launchSettings` → `IntentUtils.launchAppDetailsSettings`  

#### `app.openUrl(url)`

- **签名**：`openUrl(url)` → `void`  
- **说明**：无协议时前缀 `http://`；`Intent.ACTION_VIEW`。  
- **桥接**：`App.kt` → `openUrlInternal`  
- **实现**：`AppUtils.openUrl` / `AugmentableApp.openUrlInternal`  

#### `app.startActivity(options)` / 字符串重载

- **签名**：  
  - `startActivity('console'|'settings'|...)` — 短名称映射 `ActivityShortForm`（见 `AppUtils`）  
  - `startActivity(urlString)` — 含 `://` 或匹配「类网址」时打开浏览器  
  - `startActivity(intentOptions)` — `NativeObject` 经 `Intent.configure`  
  - `startActivity(intent, options)` — 对已有 `Intent` 再合并选项  
- **扩展**：选项对象可含 `root: true`、`shizuku: true`、`dual: true`，分别走 root shell、`WrappedShizuku`、双开用户执行（见 `App.kt`）。  
- **返回值**：`void`  
- **桥接**：`App.kt`  
- **实现**：`IntentUtils.startSafely`、双开时 `execCommandForDualUser`  

```js
app.startActivity({ packageName: 'org.autojs.autojs6', className: '...SettingsActivity_', root: true });
```

#### `app.sendBroadcast(options | name)`

- **签名**：  
  - 字符串：`inspect_layout_hierarchy` 等 → 触发布局检查（主线程协程 + `LayoutInspectEventBus`）  
  - 对象：`sendBroadcast` 构造 `Intent`；若 `root: true` 则 `am broadcast`  
- **桥接**：`App.kt`  

#### `app.intentToShell(options)`

- **签名**：`intentToShell(intentOrObject)` → `string`  
- **返回值**：去掉首尾空格后的 **shell 参数片段**（用于拼接 `am start`/`am broadcast` 等）。  
- **桥接**：`App.kt` 中 `intentToShellRhino`  
- **示例**：

```js
shell('am start ' + app.intentToShell({ packageName: '...', className: '...' }), true);
```

#### `app.uninstall(packageName)`

- **签名**：`uninstall(pkg)` → `void`  
- **实现**：`AppUtils.uninstall` → `Intent.ACTION_DELETE`  

#### `app.viewFile(path)` / `app.editFile(path)`

- **签名**：各 `(path: string)` → `boolean`  
- **说明**：桥接层要求路径经 `files` 规范化且存在、为文件。  
- **实现**：`AppUtils.viewFile` / `editFile`（`IntentUtils` + `AppFileProvider`）  

#### `app.parseUri(uri)`

- **签名**：`parseUri(uri)` → `android.net.Uri | null`  
- **说明**：字符串以 `file://` 开头时走 `getUriForFileRhinoWithRuntime`；否则 `toUri()`。  
- **桥接**：`App.kt` — `parseUriRhinoWithRuntime`  

#### `app.intent(options)`、`app.startService`、`app.sendEmail`、`app.getUriForFile`

- 与官方文档一致；`startService` 在选项含 `root: true` 时用 root 执行 `am startservice`（见 `App.kt`）。

## Device - 设备

### 模块概述

`device` **合并**了两部分：

1. **augment 层**（`augment/device/Device.kt`）：为 `device` 增加 `width`/`height` 等 getter、以及 `summary`、`vibrate`、网络与指针位置等 **新方法**。  
2. **原有 Java API**（`runtime/api/Device.java`）：大量 **静态字段**（Build 信息）与 **实例方法**（亮度、音量、内存、唤醒等），与 [Device 官方文档](https://docs.autojs6.com/device) 描述一致。

| 注册 | `ScriptRuntime.kt` 约第 **799** 行：`Device(this).augment(target, device, true)` |

### 详细 API（节选）

#### 尺寸与 Build 只读字段

- **签名**：`device.width`、`device.height`、`device.brand`、`device.model` 等 — 只读。  
- **实现**：`Device.java` 静态常量 + augment getter（宽高）。  
- **示例**：

```js
console.log(device.width, device.height, device.brand, device.model, device.sdkInt);
```

#### `device.getIMEI()` / `device.imei`

- **说明**：实例方法 `getIMEI()`；类加载后静态字段 `imei` 在构造函数中赋值（`DeviceUtils.getIMEI`）。  
- **权限**：读取 IMEI 需满足系统限制与运行时权限（参见 `ensureReadPhoneStatePermission`）。  

#### `device.getAndroidId()`

- **返回**：16 进制字符串形式的 Android ID。  

#### `device.getMacAddress()`

- **返回**：可能为 `null`；若 `WifiInfo` 返回 `02:00:00:00:00:00` 会尝试 **wlan0** 与其它回退路径。  

#### 亮度、音量、电池、唤醒等

- 与 [官方 Device 文档](https://docs.autojs6.com/device) 一致；涉及 `修改系统设置` 的方法会 `ensureWriteSettingsPermission()`。

## Shell

### 模块概述

- **全局函数 `shell(cmd, root?)`**：一次性执行命令，同步返回 **`AbstractShell.Result`**（`code` / `result` / `error`）。实现为 **`ProcessShell.execCommand`**，非交互式终端。  
- **模块对象 `shell`**（augment）：可 **调用** `shell(cmd, ...)`（`Invokable`）、并提供 `execCommand`、`getCommand`、`fromIntent`、`kill`、`currentPackage` 等（见 `Shell.kt`）。  
- **Java 类 `Shell`**：基于 **内嵌终端会话** 的长连接，适合多条命令；构造函数与 `exec` 行为见 [Shell 文档](https://docs.autojs6.com/shell) 与 `Shell.java`。

### 源码定位

| 类型 | 位置 |
|------|------|
| 全局 `shell()` | `ScriptRuntime.shell` → `ProcessShell.execCommand`（约 **538** 行） |
| augment | `runtime/api/augment/shell/Shell.kt` |
| 交互式 Shell | `runtime/api/Shell.java`（继承 `AbstractShell`） |
| 注册 | `ScriptRuntime.kt` 约 **754** 行：`Shell(this).augment(target, true)` |

### API 列表总览

| API | 作用 |
|-----|------|
| `shell(cmd[, root])` | 执行命令并返回结果对象 |
| `shell.execCommand` / 调用 `shell(...)` | 与全局 shell 类似，可解析多参数形式（见 `getCommandData`） |
| `new Shell(root?)` | 启动持久 shell 会话 |
| `Shell#exec` | 异步写入命令 |
| `Shell#exit` / `exitAndWaitFor` | 退出会话 |
| `Shell#setCallback` | 输出回调 |

### 详细 API

#### `shell(cmd, root)`

- **签名**：`shell(cmd: string, root?: boolean|number)` → `{ code: number, result: string, error: string }`  
- **参数**：`cmd` 为单条命令字符串；`root` 为是否走 root 进程（文档默认 `false`；运行时以 `withRoot != 0` 判断）。  
- **返回值**：`AbstractShell.Result`（`code` 0 表示成功）。  
- **桥接**：无单独 Kotlin 文件；入口为 `ScriptRuntime.shell`。  
- **实现**：`runtime/api/ProcessShell.java`（通过 `execCommand`）。  
- **示例**：

```js
var r = shell('getprop ro.build.version.release', false);
if (r.code === 0) console.log(r.result);
```

#### `Shell` 构造函数与实例方法

- **签名**：`new Shell()` / `new Shell(root: boolean)`（Rhino 中对应 `org.autojs.autojs.runtime.api.Shell` 的多个构造函数）。  
- **说明**：在 UI 线程初始化 `ShellTermSession`；`exec` 向伪终端写入命令，**不阻塞**等待结束；`execAndWaitFor` 可等待输出。  
- **桥接**：全局 **`Shell`** 类由 `GlobalClasses` / `Classes.kt` 暴露为 `NativeJavaClass`。  
- **实现**：`runtime/api/Shell.java`  
- **示例**：

```js
var sh = new Shell(true);
sh.exec('am force-stop com.tencent.mm');
sh.exit();
```

## Shizuku

### 模块概述

在设备已安装 **Shizuku（≥11）**、服务已启动且 **AutoJs6 已授权** 时，可通过 `shizuku` 以 **ADB 同级能力** 执行 shell（见 [Shizuku 文档](https://docs.autojs6.com/shizuku)）。底层通过 `WrappedShizuku` 绑定用户服务 `IUserService.execCommand`，并对 **binder 死亡** 做自动重连与一次重试。

### 源码定位

| 类型 | 位置 |
|------|------|
| 桥接 | `runtime/api/augment/shizuku/Shizuku.kt`（`Invokable`，`execCommand` 与 `Shell.getCommandData` 复用命令解析） |
| 实现 | `runtime/api/WrappedShizuku.kt` |
| 注册 | `ScriptRuntime.kt` 约第 **808** 行：`Shizuku(this).augment(target, shizuku, true)` |

### 桥接清单

- **方法**：`execCommand`、`getCommand`、`kill`、`currentPackage`、`currentActivity`、`currentComponent`（行为依赖 `WrappedShizuku.isOperational()`）。  
- **Getter**：`shizuku.state` → 对象，含 **`isInstalled`**、**`hasService`**、**`isRunning`**、**`hasPermission`**、**`isOperational`**。  

### API 列表总览

| API | 含义 |
|-----|------|
| `shizuku(cmd)` | 执行单行或多行命令（数组或含换行字符串），返回 `ShellResult` |
| `shizuku.execCommand(...)` | 与模块调用等价，参数格式与 `shell` 模块一致 |
| `WrappedShizuku.isInstalled` 等 | 通过 `shizuku.state` 暴露 |

### 详细 API

#### `shizuku.execCommand` / 直接调用 `shizuku(...)`

- **签名**：  
  - `shizuku(cmd: string)`  
  - `shizuku(cmdList: string[])` — 多行以 `\n` 连接  
- **返回值**：`AbstractShell.Result`（与 `shell()` 相同结构）。  
- **桥接**：`Shizuku.kt` → `scriptRuntime.shizuku.execCommand`  
- **实现**：`WrappedShizuku.execCommand` → `IUserService.execCommand`，并去除前缀 `adb shell`。  
- **示例**（摘自官方文档）：

```js
shizuku('input tap 100 120');
console.log(shizuku('date').result.trim());
```

#### `isInstalled` / `hasPermission` / `requestPermission` / `isRunning`

| 能力 | JS 访问方式 | 实现要点 |
|------|-------------|-----------|
| 是否安装 Shizuku | `shizuku.state.isInstalled` 或脚本接口 `WrappedShizuku.isInstalled(context)` | 能否 `getLaunchIntentForPackage` |
| 是否已授权 | `shizuku.state.hasPermission` | `Shizuku.checkSelfPermission()` |
| 请求授权 | **`shizuku.requestPermission()`**（若 Rhino 将 `WrappedShizuku` 的 `@ScriptInterface` 方法映射到全局 `shizuku` 对象上；底层见下方说明） | `WrappedShizuku.requestPermission()` → `Shizuku.requestPermission(mRequestCode)` |
| 服务是否运行 | `shizuku.state.isRunning` | Binder 是否已接收（`mHasBinder`） |
| 是否可操作 | `shizuku.state.isOperational` | `isRunning() && hasPermission()` |

**说明**：`ScriptRuntime.shizuku` 即单例 **`WrappedShizuku`**（见 `ScriptRuntime.kt`），`Shizuku` augment 对其做增强；授权弹窗依赖 **Activity 上下文** 与用户操作。**状态汇总**优先使用 **`shizuku.state`**；若脚本侧未识别 `requestPermission`，可通过宿主界面抽屉中的 Shizuku 开关或 `WrappedShizuku.config(...)` 引导用户到 Shizuku 应用授权。

#### `shizuku.getCommand` / `shizuku.kill` / `current*`

- **签名**：与 `shell` 模块对称；`kill` 在 Shizuku 不可用时返回 `false`。  
- **实现**：`Shizuku.kt` 调用 `WrappedShizuku` 与 `App.getPackageName`。

## 附录：与脚本全局相关的交叉引用

- **`app.autojs`**：与 **`autojs`** 同一引用，便于兼容旧脚本访问 `app.autojs.versionName` 等。  
- **`shell` 与 `shizuku`**：二者均可通过 **函数调用形式**执行命令；`Shizuku.execCommand` 内部命令拼接与 **`Shell.getCommandData`** 一致。  
- **权限**：`device` 修改系统/安全设置、`app` 启动外部组件、`shizuku` 特权命令等均可能受 **系统权限、厂商策略、Android 版本** 限制；以真机行为与官方文档为准。
